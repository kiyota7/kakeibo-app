# ローカル開発環境セットアップ

このマシンではHomebrewを使わず、sudo不要な方法でRuby/MySQLを用意している。
別のマシンでセットアップする場合は、Homebrew等を使って同等のバージョンを用意すればよい。

## 導入済みのバージョン

| ツール | バージョン | 導入方法 |
|---|---|---|
| Ruby | 3.3.12 | rbenv経由(`~/.rbenv`, sudo不要) |
| Rails | 8.1.3 | `gem install rails`(Ruby 3.3.12環境に導入) |
| Bundler | 4.0.17 | `gem install bundler` |
| Node.js / npm | v24.18.0 / 11.16.0 | 既存導入済み環境をそのまま利用 |
| Next.js | 16.2.12 | `create-next-app`でfrontend作成時に導入 |
| MySQL | 8(Dockerコンテナ) | `docker-compose.yml` |

### Rubyについて(補足)

macOS標準のRuby(2.6系)はRailsが動作しないほど古いため、[rbenv](https://github.com/rbenv/rbenv)を
`~/.rbenv`にgit clone(sudo不要)して導入し、Ruby 3.3.12をビルドしている。

このマシンにはlibyaml(YAML処理用ライブラリ)が入っておらず、`rbenv install`が
`psych`拡張のビルドで失敗する事象があった。その場合は、libyamlをソースから
sudo無しでビルドし(`~/dev-tools/libyaml`に配置)、以下のように`RUBY_CONFIGURE_OPTS`で
そのパスを指定してからインストールし直す。

```bash
RUBY_CONFIGURE_OPTS="--with-libyaml-dir=$HOME/dev-tools/libyaml" rbenv install 3.3.12
```

### データベースアダプタについて(補足)

MySQL接続には`mysql2`ではなく`trilogy`(Rails 7.1+で公式サポートされているMySQL互換の
クライアント)を採用している。trilogyは外部のMySQLクライアントライブラリ(libmysqlclient)への
依存がなく、追加のライブラリ導入なしにgemのビルドが完了するため、今回のようなsudoなし環境との
相性が良い。ローカルのDocker MySQLにも、本番のAmazon RDS(MySQL)にも同様に接続できる。

## ポート番号

- バックエンド(Rails, `backend/`): **3001**
- フロントエンド(Next.js, `frontend/`): **3000**

`frontend/next.config.ts`の`rewrites()`で`/api/:path*` → `http://localhost:3001/api/:path*`を
固定で参照しているため、バックエンドを別ポートで起動するとAPI通信が失敗する。

## MySQLの起動・停止(Docker Compose)

```bash
# 起動
docker compose up -d

# 状態確認
docker compose ps

# 停止
docker compose down

# 停止 + データも削除する場合
docker compose down -v
```

- 接続先: `localhost:3306`、DB名 `backend_development`
- 接続ユーザー: `kakeibo` / パスワード: `kakeibo`(開発環境専用の簡易パスワード)
- データはDocker named volume(`kakeibo-db-data`)に永続化される

## バックエンドアプリの起動

```bash
cd backend
bin/rails db:migrate   # 初回・スキーマ変更時
bin/rails server -p 3001
```

起動後、`http://localhost:3001/up`にアクセスするとRailsのヘルスチェックページが表示される。

DB接続情報は`config/database.yml`の`DB_USERNAME` / `DB_PASSWORD` / `DB_HOST` / `DB_PORT`
環境変数(デフォルト値は上記のDocker Compose設定と一致)で上書きできる。

## フロントエンドアプリの起動

```bash
cd frontend
npm install
npm run dev
```

起動後、`http://localhost:3000`にアクセスするとNext.jsの初期画面が表示される。
`next.config.ts`の`rewrites()`で`/api`宛のリクエストをバックエンド(`http://localhost:3001`)へ
中継しているため、バックエンドを別途起動しておけばCORSの設定なしにAPIを呼び出せる。
