# データベース設計書

MySQLを使用する。[機能一覧](機能一覧.md)を満たすため、`categories`(カテゴリ)と
`transactions`(取引)の2テーブルを中心に設計する。

## ER図

```
categories                    transactions
+----+------+------+   1    N +----+-------------+------+--------+------+
| id | name | kind |----------| id | category_id | date | amount | memo |
+----+------+------+          +----+-------------+------+--------+------+
```

- `transactions.category_id`は`categories.id`を参照する外部キー(多対1)
- 取引が「収入」か「支出」かは、紐づく`categories.kind`によって決まる
  (取引自体には種別カラムを持たせず、カテゴリ経由で判定する。これにより
  「収入用カテゴリなのに支出として登録される」といった不整合を防ぐ)

## テーブル定義

### categories(カテゴリ)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | カテゴリID |
| name | VARCHAR(50) | NOT NULL | カテゴリ名(例: 食費、交通費、給与) |
| kind | ENUM('income','expense') | NOT NULL | 収入用カテゴリか支出用カテゴリか |
| created_at | DATETIME | NOT NULL | 作成日時 |
| updated_at | DATETIME | NOT NULL | 更新日時 |

### transactions(取引)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 取引ID |
| category_id | BIGINT | NOT NULL, FK → categories.id | 紐づくカテゴリ |
| date | DATE | NOT NULL | 取引日 |
| amount | INT | NOT NULL | 金額(日本円、正の整数) |
| memo | TEXT | NULL可 | メモ(任意入力) |
| created_at | DATETIME | NOT NULL | 作成日時 |
| updated_at | DATETIME | NOT NULL | 更新日時 |

## 集計クエリの考え方(SQL練習の対象)

- **月別集計**: `transactions`と`categories`を`JOIN`し、`date`が対象月に含まれる行を対象に、
  `categories.kind`ごとに`SUM(amount)`を求める(収入合計・支出合計。差引はアプリ側または
  SQL上で`収入合計 - 支出合計`として算出する)
- **カテゴリ別集計**: 対象期間で絞り込んだ上で、`category_id`(またはカテゴリ名)ごとに
  `GROUP BY`して`SUM(amount)`を求める
- **フィルタリング**: `WHERE date BETWEEN :from AND :to`および`WHERE category_id = :category_id`
  の組み合わせで、一覧取得・集計のいずれにも同じ絞り込み条件を適用できるようにする

## 初期データ(カテゴリのプリセット案)

導入直後にカテゴリが1件もないと取引登録ができないため、以下のような初期カテゴリを
seed(初期データ投入)しておく想定(最終的な項目は実装時に調整可)。

- 支出用: 食費、交通費、日用品、娯楽、住居費、その他支出
- 収入用: 給与、その他収入
